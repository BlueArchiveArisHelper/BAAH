# BAAH GUI 设计与维护规范

本文面向 GUI 开发者及 AI 编程助手，规定当前界面的视觉语言、组件职责、使用方式，以及后续不同规模改动的实施边界与验收方式。它是持续维护的设计规范，不是逐次修改记录。

文档基于当前 NiceGUI 3.4.1 实现。代码入口及接口以仓库源码为准；调整公共组件时应同步修订本文中的对应约定。

## 1. 产品定位与基本原则

BAAH 是以动态配置表单为核心的游戏脚本编辑与运行 GUI，采用浅蓝灰工作台、表单优先、日志置底的布局。

- 主要空间用于编辑配置；导航用于定位任务，运行控制与日志有独立区域。
- 借鉴 MFAAvalonia 的柔和表面、圆角和蓝色状态，以及 ALAS 的分层导航与运行分区；布局始终服务于 BAAH 的动态表单。
- 相同语义使用相同外观，优先修订公共组件或统一样式，避免逐页复制修补。
- 视觉改造使用项目已有 NiceGUI，不引入或升级依赖。
- 主题、语言、路由、配置格式及原有操作流程继续沿用现有机制。

### 1.1 展示与业务的边界

纯 GUI 美化允许调整容器、间距、排列、颜色、字体、图标、滚动和动画。以下内容视为业务契约，不能顺带修改：

| 契约 | 需要保留的内容 |
| --- | --- |
| 配置 | 属性名、存储位置、字段类型、默认值、序列化格式 |
| 控件 | 选项、初始值、最小值、最大值、步进、精度、格式与类型转换 |
| 绑定 | `bind_value` 及其方向、转换函数、源对象、目标键 |
| 联动 | `bind_visibility_from`、条件转换、刷新范围、事件回调 |
| 执行 | 保存顺序、运行/停止流程、进程及日志绑定 |
| 动作编辑 | 对象构建、编辑回调、序列化和导入导出 |

将字段从一个容器移到另一个容器时，应原样保留控件及绑定代码。折叠、导航展开等展示状态保留在页面内，不为此添加持久化配置字段。

## 2. 代码分层与修改位置

以下路径均相对于仓库根目录。

| 层次 | 位置 | 职责 |
| --- | --- | --- |
| 公共视觉 | `gui/components/modern_ui.py` | 主题初始化、颜色变量、通用容器、导航、提醒、日志和集中 CSS |
| 页面框架 | `gui/refactor_pages/home.py` | 配置首页的组织与配置文件操作 |
| 编辑工作台 | `gui/refactor_pages/json_set_panel.py` | 页面注册、顶栏、分类导航、设置渲染、保存运行及日志连接 |
| 具体表单 | `gui/pages/Setting_*.py` | 使用既有配置和回调构建任务表单 |
| 业务编辑组件 | `gui/components/` | 列表、截图、路径、队伍强度、图表等可复用编辑区域 |
| 动作编辑器 | `define_actions/basic_objects.py` | 动作对象及其编辑界面；通过公共容器获得一致外观 |
| 多语言 | `DATA/i18n/zh_CN.json`、`en_US.json`、`jp_JP.json` | 用户可见说明及标签 |
| 回归检查 | `tests/` | 控件契约、主题初始化、多语言和图标覆盖检查 |

`modern_ui.py` 的视觉组件只接受展示内容和回调，不读取或修改业务配置。列表等已有业务组件可以继续承担其既有数据编辑职责，不能因样式封装扩大数据修改范围。

## 3. 页面结构与空间分配

### 3.1 配置首页

桌面采用主辅两栏：配置列表在主栏，项目介绍、更新、语言及主题在辅助栏。配置卡片保留进入、复制、快捷方式和删除等操作，操作区可换行。

首页最大宽度为 1600px，默认外边距 32px、主要区块间距 24px。窄屏转为单列，配置列表在前，辅助信息在后。长配置名允许换行。

### 3.2 配置编辑工作台

```text
顶部第一行：返回 / 配置名                  保存 / 运行控制
顶部第二行：区服 / ADB / 模式 / 路径等关联设置
─────────────────────────────────────────────────────
分类导航                 当前表单标题
一级分类                 默认收起的说明
分隔线与留白             当前设置内容
二级页面列表             可用空间优先分配给表单
─────────────────────────────────────────────────────
日志标题条；展开后在正常布局中占据空间
```

- 桌面编辑页使用视口高度；中间工作区可伸缩，导航和表单分别滚动。
- 顶栏分为操作和连接设置两行，路径、地址等允许换行，保留区服及 PC、Steam、序列号模式的原有联动。
- 表单正文默认内边距 24px，区域间距 16px，不通过绝对定位让底部日志覆盖表单。
- 日志默认收起，展开高度为 `min(200px, 30dvh)`，最小 120px，内部使用 Quasar 滚动区。
- 图表筛选区使用全宽、水平居中、可换行容器；筛选输入与按钮不额外添加造成纵向错位的单边距。

### 3.3 响应式规则

| 范围 | 当前布局约定 |
| --- | --- |
| 默认桌面 | 导航宽 224px，正文内边距 24px |
| 宽度 ≤1100px | 导航宽 200px，正文内边距 20px |
| 宽度 ≤899px | 工作区纵向排列，一级导航横排，二级列表最大高度 250px；提供导航收起按钮；正文内边距 16px |
| 窄屏首页 | 主辅两栏改为单列 |

窄屏编辑页恢复文档流滚动，不能继续强制桌面固定高度。Flex/Grid 子项应设置合理的 `min-width: 0`；需要收缩的滚动区域使用 `min-height: 0`。避免页面整体横向溢出；复杂编辑内容必须能在自身区域或正常文档流中到达。

## 4. 视觉语言与主题

### 4.1 主题变量

颜色集中维护在 `modern_ui.py` 的 `STYLES` 中，通过 `body.baah-page` 和 `body.body--dark.baah-page` 切换。

| 用途 / CSS 变量 | 浅色 | 深色 |
| --- | --- | --- |
| 背景 `--baah-bg` | `#F3F6FB` | `#101827` |
| 面板 `--baah-surface` | `#FFFFFF` | `#182234` |
| 柔和表面 `--baah-soft` | `#F8FAFD` | `#1D2A40` |
| 正文 `--baah-text` | `#25344B` | `#E2EAF6` |
| 辅助文字 `--baah-muted` | `#687A91` | `#A0B1C8` |
| 边框 `--baah-border` | `#E0E7F0` | `#2D3C53` |
| 文字强调 `--baah-accent` | `#2563EB` | `#93C5FD` |
| 一级选中 `--baah-category-selected` | `#BFDBFE` | `#365B88` |
| 二级选中 `--baah-page-selected` | `#F0F6FF` | `#1F3049` |

NiceGUI 主色由 `ui.colors(primary='#3B82F6', ...)` 定义。控件主色、文字强调和导航选中表面各有职责，避免用一个变量覆盖全部状态。

新样式优先引用现有主题变量。必要的新语义颜色应集中定义并同时提供明暗值，不在各页面散落固定白底、黑字或自定义蓝色。

### 4.2 字体、圆角与间距

- 字体优先使用 Segoe UI、Microsoft YaHei、sans-serif，正文基准 14px。
- 导航文字 13px；一级分类统一 `font-weight: 700`，二级选中为 650。
- 工作台表单标题约 22px，设置分组标题约 15px；辅助标签约 12px。
- 主面板圆角 12px，输入控件、导航项和提醒框通常为 8px。
- 常用间距为 8 / 12 / 16 / 24px；密集控件内部可使用较小间距，需保持同类一致。
- 悬停和选中等过渡约 150ms；遵循 `prefers-reduced-motion`，减少动画时关闭过渡和动画。

### 4.3 导航层级

一级分类负责切换页面集合，二级页签负责定位具体表单。一级通过粗体和更明显的选中背景突出层级；二级使用浅选中背景、强调文字和左侧 3px 标记。保留分隔线，其上下各 12px 留白。

两级均为左侧图标、右侧文字，图标约 18px，间距 8px。二级名称允许换行，图标不被挤压。

图标映射集中在 `CATEGORY_ICONS` 和 `PANEL_ICONS`：

- 一级使用稳定分类值 `0 / 1 / 2`，分别为 `settings / event_note / build`。
- 二级使用 `ConfigPanel.nameID`，不按翻译后的名称匹配。
- 使用 NiceGUI 现有图标资源，保留完整文字，不把导航变成仅图标操作。
- 新增注册页面时同步补齐 `PANEL_ICONS`，运行图标覆盖检查。

## 5. 公共组件与使用方式

### 5.1 主题初始化

`apply_theme()` 负责 NiceGUI 默认属性、默认类、默认样式、`ui.colors`、页面根类和集中 CSS 注册。使用 NiceGUI 官方的 `default_props`、`default_classes`、`default_style` 等接口，不修改包内源码。

必须在等待浏览器连接前注册主题样式。真实路由采用以下顺序：

```python
from gui.components.modern_ui import apply_theme
from gui.components.web_dark_mode import apply_dark_mode
from gui.define import gui_shared_config

# 页面路由函数开头：先注册样式，再处理可能等待浏览器的系统主题。
apply_theme()
await apply_dark_mode(gui_shared_config)
```

`apply_theme()` 中默认控件样式按进程初始化一次，但每个页面仍需调用它注册页面 CSS。不能将整个函数放入只执行一次的全局分支，也不能因浅色预览正常就省略“跟随系统”的首次加载检查。

### 5.2 视觉组件目录

以下函数均位于 `gui/components/modern_ui.py`。

| 接口 | 用途与返回约定 |
| --- | --- |
| `page_shell(*, home=False)` | 返回首页或编辑页根 `ui.column`，统一宽度、高度和外边距 |
| `surface(extra='')` | 返回公共面板 `ui.card`，`extra` 用于添加语义类 |
| `form_row()` | 返回允许换行、垂直居中的表单 `ui.row` |
| `form_grid()` | 返回自适应 Grid 容器；常规分组目标宽约 280px，窄屏单列 |
| `setting_group(title=None)` | 上下文管理器，提供公共面板及可选标题，`as` 得到该卡片 |
| `operation_bar()` | 返回可换行操作行，统一按钮间距 |
| `navigation_item(label, selected, on_click, *, icon=None)` | 返回原生按钮，选中仅改变展示，回调由调用方负责 |
| `notice_box(text, *, tone='info')` | 返回静态提醒容器；支持 `info`、`warning`，无关闭按钮 |
| `description_panel(title)` | 返回默认收起的说明 `ui.expansion` |
| `log_panel(title)` | 创建折叠外壳并返回其中的 `ui.log` 实例，便于连接现有日志源 |
| `style_chart_options(options)` | 修改并返回图表主题选项；用于当前含 `xAxis` 和列表型 `yAxis` 的历史图表 |

这些是可复用构件，不要求把所有老页面一次改写为相同嵌套结构。已有内容能通过统一外层获得正确布局时，优先保留内容构建逻辑。

### 5.3 设置分组和表单行示例

```python
from nicegui import ui
from gui.components.modern_ui import setting_group, form_row, operation_bar

def render_buy_ap_rules(config, original_save_callback):
    # 只封装布局；字段、绑定方向及原有回调保持不变。
    with setting_group(config.get_text('task_buy_ap')):
        with form_row():
            ui.number(
                config.get_text('config_buy_ap_max_price'),
                min=0, precision=0, step=30,
            ).bind_value(
                config.userconfigdict, 'BUY_AP_MAX_PRICE',
                forward=lambda x: int(x),
            )
        with operation_bar():
            ui.button(config.get_text('button_save'), on_click=original_save_callback)
```

示例展示组合方式。实际迁移应复制原控件的完整参数，不用示例代替项目原有选项或数值约束。普通设置页由工作台统一提供 `baah-form` 外壳，不应在每个子页面重复调用 `page_shell()` 或创建日志面板。

### 5.4 提醒与帮助文字

```python
from gui.components.modern_ui import notice_box

# 蓝色信息图标；正文沿用主题文字色。
notice_box(config.get_text('desc_one_click_raid'))

# 琥珀色警告图标，用于需要用户注意的规则和风险。
notice_box(config.get_text('config_buy_ap_rules_notice'), tone='warning')
```

- `notice_box` 以文字参数决定内容，以 `tone` 显式决定样式，不比较中文、英文或日文字符串。
- 图标与正文分列，正文支持长文字和换行；不可仅依赖颜色传达意义。
- 普通字段解释使用 `.baah-help-text`，与字段一起放入 `.baah-described-field`，解释位于输入框上方；保留原 placeholder 和控件尺寸约束。
- `.baah-resource-guide` 用于资源说明、主页链接和视频的成组排列。
- 当前 BAAH 运行注意事项沿用 `.baah-notice` / `.baah-notice-text`；新增通用提醒优先使用 `notice_box`。

### 5.5 二维与三维列表编辑

`gui/components/list_edit_area.py` 的接口为：

```python
def list_edit_area(
    datadict, linedesc, blockdesc='', has_switch=False,
    min_value_for_1st_dim=1,
    min_value_for_2nd_dim=1,
    min_value_for_3rd_dim=-99,
    *, blockdesc_as_notice=False,
):
    ...
```

- `datadict` 传入已有可变列表，保留原引用；组件在原位置编辑并通过 `ui.refreshable` 更新显示。
- `linedesc` 决定编辑结构；`has_switch` 决定条目开关结构。不得为排版更改维度或自动转换数据类型。
- 三个最小值参数沿用既有含义；美化不能重设默认值或改变调用处的实际参数。
- `blockdesc_as_notice=False` 保持原有普通说明；显式设为 `True` 时将整个区块说明展示一次提醒框。
- 空任务行统一调用 `notice_box`；当前实现对 `config_no_tasks_set_here` 使用 `tone='warning'`，提示对应日期可能跳过该任务。
- 增删由原有方法执行后刷新，不在页面外围再渲染一份空状态或区块说明。

一键扫荡的用法见 `gui/pages/Setting_Oneclick_Raid.py`：保留原有列表参数，仅通过 `blockdesc_as_notice=True` 选择说明外观。

### 5.6 其他常用编辑区域

| 区域 | 当前复用方式 | 扩展时的边界 |
| --- | --- | --- |
| 队伍强度 | `edit_team_strength.py` 使用 `form_row()` 和 `.baah-team-row` | 保留队伍/颜色顺序、范围和整数转换 |
| 截图预览 | `cut_screenshot.py` 使用 `.baah-image-preview` 与公共表单行 | 保留图片源绑定、截图参数、异步操作和回填 |

## 6. 表单联动与 CSS 的关键约定

### 6.1 保留动态显隐

容器改变后，原有 `bind_visibility_from` 及其转换函数仍应作用于相同内容范围。不得增加会强制显示隐藏表单的规则，例如为所有行无条件写 `display: flex !important`。

需要换行、间距等外观时，优先添加语义类和普通样式，不接管 NiceGUI 的可见性状态。窄屏导航收起类只控制导航展示，不复用为业务字段的隐藏机制。

### 6.2 输入标签、值、单位和附加控件

`.baah-form` 内的有标签输入采用统一布局：标签独占第一行，前缀、输入值和后缀共用第二行。长标签可以换行，数字与 `suffix` 单位必须保持同行。

- 使用现有 Grid 规则分配前缀、数值和后缀，不通过把单位改成独立 label 修补。
- 单位设置不换行；输入区允许收缩，不能让 `width: 100%` 与后缀互相挤出一行。
- 下拉、清除、密码及日期等附加按钮对齐输入值一行，而不是对齐标签行。
- 修改 `.q-field__*` 规则时，必须连带检查数字框、普通输入、下拉框、文本域和附加按钮。
- 保留错误、禁用和键盘焦点状态，不通过隐藏边框或图标掩盖问题。

### 6.3 滚动与实例生命周期

- 设置页可重建其展示区域，但不应重新创建工作台的日志源。
- 日志在注册设置页前创建，后续传给页面和运行回调；折叠只改变内容可见性。
- 保留独立二级导航滚动和表单滚动；不要给日志外壳叠加重复滚动条。
- 弹窗、下拉菜单不得被新加的 `overflow: hidden` 裁切；新容器需要验证其弹出层表现。

### 6.4 样式的作用域

优先顺序是：现有组件 → 新增可复用组件或变体 → 集中语义类 → 必要的局部调整。

公共规则放在 `modern_ui.py` 并以 `.baah-*` 或 `.baah-page` 限定作用域。避免按元素 ID、页面位置或翻译文本设置样式。不得在多个页面复制相同 CSS；局部例外应有中文注释，说明用途和不能采用公共规则的原因。

NiceGUI 默认属性是全局约定，修改前必须确认影响范围；覆盖组件内部结构时仅使用当前版本实际存在的结构。升级 NiceGUI 或改变主题初始化属于全局改动，不能作为小型样式修复顺带处理。

## 7. 多语言规范

- 新增用户可见说明、提醒和标签，应使用当前 `config.get_text(key)` 或对应软件配置对象，不将中文直接写进页面。
- 中、英、日三份 JSON 同步新增同名键；在相同语义位置插入，保持对应字段物理行号一致。
- 每个值保留一个物理行，需要文字换行时使用 JSON 转义，不整体重排或格式化语言文件。
- 同一个键的不同语言应表达相同条件、行为和后果；特别保留“无任务时跳过”等操作含义。
- `nameID`、配置属性、分类枚举等机器标识不翻译。图标和布局分支不根据翻译文本推断。
- 修改后检查 JSON 可解析、无重复键、三语键齐全，并使用英文/日文长标签验证换行。

现有提示键包括 `desc_project_resources`、`desc_noti_content_diy_hint`、`config_buy_ap_rules_notice`、`config_no_tasks_set_here`、`desc_one_click_raid`。字段位置应跟随对应语义区域，不将本规范中某个固定行号视为永久接口。

## 8. 后续改动的规模与实施要求

规模按影响范围判定，不按修改行数判定。一个全局 CSS 选择器即使只改一行，也可能属于全局改动。

| 级别 | 典型范围 | 实施要求 | 最低验收范围 |
| --- | --- | --- | --- |
| 局部 | 单个页面的一段提示、独有区域间距或内容分组 | 先复用已有组件；必要的例外添加中文注释；新文案同步三语 | 目标页面、相关联动、明暗主题、桌面与窄屏、长标签 |
| 组件级 | 公共提醒、列表编辑器、路径行、导航项或一类控件 | 修改公共组件/语义类；新增接口优先采用带默认值的可选关键字参数；检查所有调用点 | 所有受影响调用类型、边界数据、刷新、键盘及相关绑定回归 |
| 全局 | 主题变量、默认控件样式、工作台布局、断点、输入内部结构或日志生命周期 | 先列影响面与不变契约；集中实现；分阶段验证；同步维护规范 | 首页及全部已注册面板、三语/明暗/系统主题、各目标尺寸、真实入口及操作回归 |
| 涉及业务 | 新配置字段、数值规则、保存策略、运行行为或序列化变化 | 作为明确的功能变更处理，说明行为差异；不能并入“仅美化”的提交范围 | 除视觉检查外，增加相应业务与兼容性验证 |

### 8.1 什么时候抽组件

- 同一布局已用于多个位置，或同类问题在多个页面出现，应抽取/扩展公共组件。
- 即使目前只有一个调用点，若是稳定的通用交互模式，也可以先封装，但不要引入与展示无关的状态管理。
- 仅某个页面有独特内容，已有容器组合能表达时，直接组合现有组件即可，不为单次间距新增复杂抽象。
- 组件变体使用清晰的语义参数，例如 `tone='warning'`、`blockdesc_as_notice=True`；保持旧调用兼容。
- 修改公共组件前检索所有调用点；新增页面遵循现有注册机制，并补齐多语言、分类和图标。

### 8.2 工作流程

1. 检查分支及暂存/未暂存改动，保留用户工作；记录此次任务的实际影响范围。
2. 阅读受影响组件、所有调用点及原有控件参数，确定展示层与业务层边界。
3. 优先实现公共规则，再接入页面；为新增组件和局部例外添加中文注释。
4. 验证相关状态及窗口尺寸；发现公共问题时回到组件修复，不在每页追加覆盖。
5. 运行相应回归检查，复核差异，确认没有配置、依赖或业务行为的附带变化。
6. 交付时说明效果、验证范围和真实限制；公共接口或设计约定变化时更新本文。

## 9. 验收方法

### 9.1 环境与入口

所有项目 Python 命令均先激活已有 conda 环境。在项目根目录使用：

```bat
activate baah
python jsoneditor.py
```

当前真实入口 `ui.run(..., reload=False)`，源码变化后需要重新启动 GUI 并刷新浏览器。必须区分真实入口验证与独立预览验证；独立预览正常不能代替真实入口首次加载检查。

### 9.2 现有自动检查

```bat
activate baah
python tests/check_gui_contracts.py
python tests/test_theme_bootstrap.py
python tests/test_gui_details_i18n.py
```

| 检查 | 覆盖内容 | 局限 |
| --- | --- | --- |
| `check_gui_contracts.py` | 原有控件参数、绑定、回调、关键业务函数及源码语法 | 不证明页面没有遮挡，也不覆盖所有运行时行为 |
| `test_theme_bootstrap.py` | 两个真实路由在等待连接前注册主题样式 | 不代替浏览器中的系统主题首次加载和刷新 |
| `test_gui_details_i18n.py` | 目标翻译键、重复键、物理行号及已注册面板图标覆盖 | 新增提示键应按需要扩展覆盖，不自动验证翻译质量 |

现有检查仅依赖标准库，无需安装测试依赖。若本地忽略规则使 `tests/` 未被追踪，交付回归检查时应明确这些文件的状态，不通过修改忽略规则混入额外变更。

不能为让纯美化通过而直接重写参数基线。对确认过的合法显示差异，采用范围明确的兼容处理；业务契约变化必须单独说明并验证。

### 9.3 人工与浏览器检查矩阵

按改动规模裁剪检查范围；全局改动至少覆盖以下项目：

- 视口：1920×1080、1366×768、1024×768，以及低于 900px 的窄窗口；检查 125% 缩放。
- 主题与语言：浅色、深色、“跟随系统”；中文、英文、日文。首次加载和刷新均需正确加载样式。
- 导航：层级区分、图标、选中态、长名称、独立滚动及窄屏收起。
- 表单：区服与 ADB 模式、咖啡厅、商店、日程、活动、通知和自定义动作等关联显隐。
- 输入：数字与单位同行，附加按钮对齐，禁用/错误/焦点状态可见，键盘可到达。
- 列表：空行、增删、二维/三维、开关、刷新后提示及说明不重复。
- 编辑与持久化：使用独立测试配置，保存后重新加载；通知文本和购买体力等值与输入一致。
- 操作区：日期筛选、菜单、弹窗、上传/下载与动作导入导出在相应改动范围内可用。
- 日志与运行控制：通过隔离测试源检查展开/收起、状态切换、页面切换及日志实例绑定；不以真实购买、发送通知或启动游戏替代展示测试。

验收标准是：没有内容遮挡、按钮裁切、无法到达的字段、因布局造成的误改值或失效操作；所有受影响状态可观看、浏览和操作。静态检查通过后仍需查看实际界面。
